# 定时调度

## 职责与接入

`UniTimerManager` 是本项目定时调度入口 由 `ModuleHub` 注册并唯一调用 `Init` 根节点释放时调用 `Dispose`

本次保留全部 `PlayerLoopTiming` 而不是强制合并到 `MonoManager.Update` 每个阶段仅注册一个 `IPlayerLoopItem` 全部任务由 `TimerScheduler` 集中维护 不再为每个任务创建 Stopwatch CancellationTokenSource 与逐帧异步循环

初始化依赖 UniTask 默认的全部阶段注入 未注入阶段会使初始化直接失败并释放此前注册驱动器 不会静默改到 Update 不新增程序集依赖 不引入 A 侧 BaseGameManager ZLog 或管理器生命周期

`TimerScheduler.Tick` 接收阶段 缩放时间增量 非缩放时间增量与渲染帧号 内核不读取 Unity 全局时间 不对业务暴露 Tick 接口

全部定时器 API 仅允许在 Unity 主线程调用 回调也在对应 PlayerLoop 主线程阶段执行 这里不是后台线程定时器 不提供跨线程容器同步

## 使用

```csharp
var TimerManager = ModuleHub.Instance.GetManager<UniTimerManager>();
long TimerId = TimerManager.StartTimer(1f, OnTimer);
TimerManager.PauseTimer(TimerId);
TimerManager.ResumeTimer(TimerId);
TimerManager.StopTimer(TimerId);

long LoopId = TimerManager.StartRepeatingTimer(
    startDelay: 0.5f,
    interval: 1f,
    loopCount: 3,
    action: OnTimer,
    ignoreTimeScale: false,
    catchUpMode: TimerCatchUpMode.CatchUp,
    maxCallbacksPerTick: 4);
```

`OnTimer` 为调用者自己的无参回调 不要在业务方法中重复调用管理器 Init

## 参数与执行契约

| 项目 | 规则 |
| --- | --- |
| 单次任务 | StartTimer 执行一次 action 保留可空语义 |
| 首次延迟 | 有限且大于等于零 负数 NaN Infinity 立即抛异常 不自动修正 |
| 循环间隔 | StartRepeatingTimer 要求有限且大于零 action 不可空 即使次数为一也遵守 |
| 循环次数 | 正数表示实际回调总数 包含第一次 负数无限循环 零立即抛异常 |
| ID | 实例内从一递增的 long 停止任务与 StopAll 不重置 不使用哈希 不复用 溢出抛异常 |
| ID 所属 | ID 仅在原管理器实例中有效 跨实例不要混用 |
| 注册顺序 | 同阶段按注册顺序执行 跨阶段由 Unity PlayerLoop 排序 |
| 创建帧 | 创建当帧不扣时间也不执行 下一渲染帧的对应阶段才参与驱动 固定阶段同帧后续步也不例外 |
| 零延迟 | 不在创建调用栈执行 时间域增量为零时冻结 包括零延迟和补执行积压 |
| 完成 | 最后一次回调前 ID 已失效 已释放回调字段 引用仅由当前调用栈短暂持有 |
| 取消 | StopTimer 立即使 ID 失效并释放回调 引用存在则返回 true 不存在返回 false 回调自身可取消 |
| 暂停 | 暂停期间不累计剩余时间 恢复不补暂停期间的时间 改变状态返回 true 否则 false |
| 全部暂停 | 仅影响当时存在的任务 后续新增任务不自动继承 暂停与恢复全部任务均包含非缩放任务 |
| 剩余时间 | 距下次回调的秒数 已完成 已取消或已到期积压返回零 暂停时保持不变 |
| 活跃数量 | 包含暂停与等待下一帧任务 不包含已取消与已完成任务 |
| StopAll | 立即停止所有现有任务 仍允许后续创建 新任务不会被当前轮回收误删 |
| Dispose | 幂等 停止所有任务 立即断开驱动器对内核的引用 驱动器下一轮自动注销 禁止再创建或初始化 |

缩放任务使用 `Time.deltaTime` 非缩放任务使用 `Time.unscaledDeltaTime` 固定阶段分别使用 `Time.fixedDeltaTime` 与 `Time.fixedUnscaledDeltaTime`

`FixedUpdate` 与 `LastFixedUpdate` 仍受 Unity 固定阶段调度控制 `timeScale = 0` 时阶段不运行 即使 ignoreTimeScale 为 true 也不会凭空触发 UI 与真实时间倒计时应选择 Update 等非固定阶段

## 卡顿策略

- `SkipMissed` 默认策略 每次阶段驱动每个任务最多执行一次 跳过已经遗漏的周期并保留原有周期相位 遗漏周期不消耗 loopCount 因此有限任务仍会执行指定总次数
- `CatchUp` 按到期周期补执行 每次阶段驱动每个任务最多执行 maxCallbacksPerTick 次 默认值为 `UniTimerManager.DefaultMaxCallbacksPerTick` 即 32 超限积压保留在剩余时间内 后续驱动继续处理 不静默丢弃
- 上限按每个任务每次阶段驱动计数 不是全局每帧预算 同一渲染帧可能有多次 FixedUpdate 总回调工作量仍取决于任务数量与业务回调成本
- 回调中暂停或取消自身会立即阻止剩余补执行

## 回调重入与异常

驱动开始固定本轮列表范围 回调新增任务可以立即返回 ID 但创建帧内任何阶段都不会执行该任务

驱动期间取消只标记失效并移除 ID 索引 清空回调 记录受影响阶段 列表结构删除在安全阶段原地压缩所有受影响阶段 不依赖被取消任务所属阶段再次运行 不即时复用任务对象 因此自取消 取消其他任务 StopAll 后新增与回调内 Dispose 均不会改变已有遍历位置

回调抛异常会立即取消该任务 保留原始异常并附带任务 ID 与阶段 同阶段其他任务继续正常驱动 阶段结束抛出 AggregateException 不吞异常

UniTask 会移除抛异常的 IPlayerLoopItem 驱动器仅对内核聚合报告的业务回调异常重新排入后继续抛出 由 UniTask 正常异常通道报告 不会因一个业务回调错误永久停止整个阶段 定时器不会自动重试出错的业务回调 其他驱动异常不重排 按 Fail fast 暴露并停止该阶段驱动

递归 Tick 被明确禁止 业务只能调用创建 暂停 恢复 取消 查询与释放接口

## 后台方法边界

`DelayRunBgComplete` 与 `DelayRunBg` 保留在 `UniTimerManager.Background.cs` 不属于定时器列表 不参与 StopAll PauseAll 或 Dispose

两者新增可选 cancellationToken 参数 生命周期由调用者管理 延迟使用 UniTask 原有默认缩放时间 行为未改为非缩放时间 令牌能阻止尚未开始的委托或后续回调 已经运行的同步委托不能被强行中断 不允许在工作委托中调用 Unity 主线程 API

## 兼容变化

- StartTimer 返回值与所有 ID 参数由 int 改为 long 显式声明 int 的外部调用方需要改成 long 或 var 已编译外部程序集需要重新编译
- 原公开 TimerInfo 无工程调用方 本次移除该实现类型 不再暴露每个任务的 CTS 与可变计时状态
- ignoreTimeScale 原来只保存参数而实际统一用 Stopwatch 本次正式生效 默认 false 的任务现在会随 timeScale 暂停或缩放
- 零延迟不再同步回调 创建当帧不参与时间累计 完成任务在最后一次回调前已经失效
- 未初始化与已释放管理器禁止创建任务 不会接受没有驱动器的任务
- 不再为普通暂停 取消与查询输出逐次 Debug.Log 不将正常控制路径变成日志热路径

## 性能边界

每个阶段遍历本阶段任务 仅对发生取消或完成的阶段稳定压缩列表 复用阶段集合而不每帧创建临时集合 异常路径才收集异常 创建任务仍分配任务对象 暂不增加对象池与堆式调度复杂度

驱动外单次取消的列表删除为 O(n) 大量高频取消是否需要换索引结构应根据目标平台 Profiler 决定 一万任务一致性检查不代表帧耗时或 GC 预算达标
